# Git — Exercices Niveau 3 (Avancé)

Objectif : situations proches de cas professionnels réels (internals, réécriture d'historique, debugging, automatisation).

1. **Exploration des internals.** Dans un dépôt avec au moins un commit, retrouve à la main (avec `git cat-file -p` et `git ls-tree`) : le hash du commit `HEAD`, le hash du `tree` qu'il référence, et le hash du `blob` correspondant à un fichier précis. Vérifie que le contenu du blob correspond bien au contenu du fichier sur disque.
2. **Secret accidentellement commité.** Commite un fichier `secret.env` contenant une fausse clé API, fais 2-3 commits supplémentaires après, puis retire complètement `secret.env` de **tout** l'historique (pas seulement du dernier commit) avec `git filter-repo`. Vérifie qu'aucun commit de l'historique ne contient plus ce fichier.
3. **Bisect automatisé.** Crée un dépôt avec au moins 10 commits où un bug (ex: une fonction qui retourne un résultat faux) est introduit à un commit "caché" au milieu. Écris un petit script de test qui retourne un code de sortie 0 (bon) ou 1 (mauvais), puis utilise `git bisect start` + `git bisect run ./test.sh` pour trouver automatiquement le commit fautif.
4. **Rebase interactif avancé.** Sur une branche de 6 commits, utilise `git rebase -i` pour : réordonner deux commits, fusionner deux commits consécutifs avec `fixup` (en gardant seulement le message du premier), et reformuler (`reword`) le message d'un troisième commit — le tout en une seule session de rebase interactif.
5. **Worktrees.** Depuis un dépôt où tu as du travail en cours non commité sur `main`, utilise `git worktree` pour ouvrir en parallèle une branche `hotfix/urgent` dans un second dossier, sans toucher à tes modifications en cours dans le dossier principal.
6. **Hook de qualité.** Écris un hook `pre-commit` (en bash ou en JS via un `#!/usr/bin/env node`) qui bloque un commit si un fichier stagé contient la chaîne `TODO` ou `console.log`, avec un message d'erreur clair indiquant le fichier et la ligne concernés.
7. **Scénario de production.** Une régression est détectée en production. Tu identifies le commit fautif avec `bisect`, mais ce commit a déjà été mergé dans `main` et déployé plusieurs fois. Explique et applique la stratégie correcte pour l'annuler sans réécrire l'historique public (justifie ton choix entre `revert` et une réécriture d'historique).
